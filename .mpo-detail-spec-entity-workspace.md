# Detail-Spec: Worker 3 — Entity-Status + Workspace Fixes

## Bugs

### RT-9/RT-15/RT-W7: Running-Indicator nur bei Orchestrator (MUST)

**Dateien:**
- `src/renderer/components/LauncherCell.tsx` (Popup mit Status-Anzeige)
- `src/renderer/hooks/useEntityPresets.ts` (Entity-Status-Berechnung)
- `src/main/session/entity-registry.ts` (Entity-Registrierung)

**Problem:** Im LauncherCell-Popup zeigt nur der Orchestrator "laeuft" + blauer Punkt + Resume-Button. Companion, Watchdog, MPO laufen ebenfalls aber ohne Indikator.
**Vermutete Ursache:** Rest der alten hardcoded Entity-Logik. entityStatus wird nur fuer bestimmte Preset-IDs berechnet statt dynamisch fuer alle laufenden Sessions.

**Fix:** entityStatus-Berechnung generisch machen — fuer jeden Preset pruefen ob eine aktive Session mit diesem entityId laeuft, nicht nur fuer "orchestrator".

**Screenshot zur Referenz:** `~/Desktop/Bildschirmfoto 2026-04-30 um 11.25.34.png`

**Testcase:** Companion, Watchdog, MPO starten → alle zeigen "laeuft" + Punkt + Resume im Popup.

### RT-6: Workspace-Popup falscher Aktiv-Status (SHOULD)

**Dateien:**
- `src/renderer/components/WorkspacePopup.tsx`
- `src/main/workspace/workspace-manager.ts`

**Problem:** TESTINGMUX zeigt "AKTIV" nach Neustart obwohl kein Workspace geladen wurde. Persistiert falsch.
**Fix:** Aktiv-Status beim App-Start zuruecksetzen wenn kein Workspace explizit geladen wurde. Oder: Aktiv-Status nur setzen wenn der Workspace tatsaechlich angewendet wird.

**Testcase:** Workspace-Stern entfernen → App neu starten → kein Workspace als aktiv markiert.

### RT-12/RT-13: Workspace-Editor Preset/Pfad-Auswahl wird nicht gespeichert (SHOULD)

**Dateien:**
- `src/renderer/components/EntityPickerPopup.tsx`
- `src/renderer/components/WorkspacesTab.tsx` oder `WorkspacesWindow.tsx`

**Problem:** EntityPickerPopup oeffnet korrekt (RT-11 PASS), aber die Auswahl wird nicht in den Workspace uebernommen. Preset und Pfad gehen beim Schliessen des Popups verloren.
**Fix:** onSelect-Callback des EntityPickerPopup muss die Auswahl in den Workspace-State schreiben, nicht nur das Popup schliessen.

**Testcase:** Workspace editieren → Preset via EntityPickerPopup auswaehlen → Popup schliesst → Preset ist im Workspace gespeichert.

## Meta-Requirements

- Running-Indicator ist MUST — die anderen beiden SHOULD
- Keine hardcoded Entity-IDs mehr — alles dynamisch
