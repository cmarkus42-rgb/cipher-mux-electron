# SP-1: Session Lifecycle

## Ziel
Session-Management reparieren: Restore nach Neustart, beendete Sessions korrekt erkennen, --resume entfernen.

## Bugs

### B06 — Session-Restore nach Neustart (KRITISCH-HOCH)
**Symptom:** Nach App-Neustart sind Sessions nicht im Grid, sondern unter "verwaiste Sessions". Kein Auto-Restore.
**Erwartung:** Restore-Dialog beim Start: "Geschlossen mit aktiven Sessions — wiederherstellen?" Ja/Nein.
**Relevante Dateien:**
- `src/main/session/session-manager.ts` — Session-Lifecycle
- `src/main/session/session-store.ts` — Persistenz
- `src/renderer/components/RecoveryDialog.tsx` — Bereits vorhanden! Pruefen ob funktional
- `src/main/main.ts` — App-Startup
- `src/renderer/app.tsx` — Renderer-Startup

**Hinweis:** Es gibt bereits eine `RecoveryDialog.tsx` — pruefen ob sie korrekt eingebunden ist und ob der Session-Store die Grid-Positionen korrekt persistiert/restored.

### B10 — Beendete Session blockiert Neustart (HOCH)
**Symptom:** Session wird als "laufend" angezeigt obwohl beendet. Neue Session nicht startbar an der Position.
**Erwartung:** Session-Status wird korrekt auf "stopped"/"exited" gesetzt wenn der Claude-Prozess beendet ist.
**Relevante Dateien:**
- `src/main/session/session-manager.ts` — Status-Tracking
- `src/main/tmux/tmux-manager.ts` — tmux Pane-Status pruefen
- `src/main/monitoring/statusline-monitor.ts` — Monitoring
- `src/main/agent/adapters/claude-code.ts` — Claude-Prozess-Lifecycle

**Hinweis:** Vermutlich fehlt ein Exit-Handler oder der tmux-Pane-Status wird nicht regelmaessig gepollt.

### B11 — Sessions starten mit --resume (HOCH)
**Symptom:** Spezialisten-Sessions (MPO, Orchestrator etc.) nutzen `--resume`, sollen aber immer frisch starten.
**Erwartung:** Kein `--resume` Flag bei Session-Start. Jede Session startet mit frischem Context.
**Relevante Dateien:**
- `src/main/agent/adapters/claude-code.ts` — Claude-CLI-Aufruf
- `src/main/session/session-manager.ts` — Session-Erstellung
- `src/main/session/mpo-template.ts` — MPO-spezifische Config
- `src/main/session/orchestrator-template.ts` — Orchestrator-spezifische Config

**Aktion:** `--resume` aus allen Claude-CLI-Aufrufen entfernen. Grep nach `--resume` im gesamten Projekt.

### FR5 — Session-Restore-Dialog
**Beschreibung:** Beim Start: "Geschlossen mit aktiven Sessions — wiederherstellen?" Ja/Nein.
**Hinweis:** Ueberschneidet sich mit B06. RecoveryDialog.tsx existiert bereits — aktivieren und testen.

## Testcases

1. App starten mit 0 vorherigen Sessions → kein Dialog
2. App starten mit vorherigen Sessions → Restore-Dialog erscheint
3. Restore-Dialog: "Ja" → Sessions im Grid an alter Position
4. Restore-Dialog: "Nein" → Grid leer, Sessions aufgeraeumt
5. Session beenden (exit in Claude) → Status wechselt auf stopped, Zelle wird frei
6. Neue Session in Zelle einer beendeten Session → funktioniert
7. `grep -r "resume" src/` → kein --resume in Claude-CLI-Aufrufen
8. Spezialisten-Session starten → kein --resume im tmux-Pane sichtbar

## Qualitaets-Gate
- Alle 8 Testcases PASS
- Kein --resume in Codebase
- RecoveryDialog korrekt eingebunden
- Session-Status-Updates zuverlaessig (Exit erkennen innerhalb 5s)
