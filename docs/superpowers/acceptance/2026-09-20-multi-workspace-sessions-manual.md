Manual acceptance for Multi-Workspace-Sessions (Task 12). Run this after `npm start` (not `electron .` — the prestart hook rebuilds better-sqlite3 against the Electron ABI; after `npm run test` the module is built for Node and the MessageBus is unavailable).

Prerequisites: two workspaces already configured in the Workspaces window (call them A and B), each with a Companion and a Debugger cell/preset available in its launcher. For steps T-MWS.9 and T-MWS.10, enable Keep Working in Settings before starting. `~/.config/cipher-mux/runs/` is the run-directory base; `_global` under it is the sentinel for unbound sessions and is never pruned.

## Multi-Workspace-Sessions

- [ ] **T-MWS.1** Workspace A aktivieren, Launcher oeffnen, Companion starten — Companion laeuft in A, PaneHeader/Grid-Zelle zeigt kein Workspace-Badge (Session-Workspace == aktiver Workspace)
- [ ] **T-MWS.2** Launcher erneut oeffnen, bei Companion den zweiten Start-Button (⤳) klicken, Workspace B waehlen — eine zweite Companion-Instanz startet in B, der aktive Workspace bleibt A, kein "already running"-Fehler
- [ ] **T-MWS.3** Terminal: ls ~/.config/cipher-mux/runs/ zeigt zwei Verzeichnisse (eines pro Workspace-ID) mit je einem companion Unterordner; cat ~/.config/cipher-mux/runs/*/companion/CLAUDE.md | grep -A2 "## Workspace Prompt" zeigt fuer beide Workspaces unterschiedliche Prompt-Abschnitte
- [ ] **T-MWS.4** Terminal: grep -l X-Mux-Workspace ~/.config/cipher-mux/runs/*/companion/.mcp.json findet beide Dateien, und grep X-Mux-Workspace ~/.config/cipher-mux/runs/*/companion/.mcp.json zeigt fuer beide eine andere Workspace-ID im Header
- [ ] **T-MWS.5** Companion-Session aus B ist in Workspace A nicht im Grid, aber in der Sidebar unter Background Sessions sichtbar, mit Workspace-Badge "B" (Workspace-Name von B) und Tooltip "Laeuft in Workspace: B"
- [ ] **T-MWS.6** Debugger (singleInstance) in Workspace A starten. Launcher oeffnen — die Karte zeigt A als laufend (Punkt-Indikator). Beim zweiten Start-Button (⤳) Workspace B waehlen — der Debugger startet in B, wirft nicht "already running", weil singleInstance pro Workspace gilt
- [ ] **T-MWS.7** Debugger in Workspace A ein zweites Mal ueber den Haupt-Start-Button (nicht ⤳) starten — wirft "already running", weil in A bereits eine Instanz laeuft
- [ ] **T-MWS.8** Eine Session ohne Workspace-Bindung starten (z.B. per Shell-Button/Freies Terminal ohne Workspace-Kontext), waehrend Workspace A aktiv ist — Session zeigt das Badge "ohne Workspace" statt gar kein Badge, sowohl im Grid als auch in der Sidebar
- [ ] **T-MWS.9** Keep Working aktivieren, Cmd+Q, App neu starten — beide Companion-Instanzen (A und B) und der B-Debugger kommen zurueck, Badges stimmen weiterhin (B-Sessions zeigen Badge in A-Ansicht, A-Sessions nicht), cat /tmp/kw-debug.json zeigt ein workspaceId-Feld pro recovered Session
- [ ] **T-MWS.10** Workspace B in der Workspaces-Verwaltung loeschen, waehrend seine Sessions noch laufen — B-Sessions laufen weiter, ihr Badge wechselt von "B" auf die rohe Workspace-ID mit einem "(geloescht)"-Zusatz. App neu starten (Keep Working weiterhin aktiv) — ls ~/.config/cipher-mux/runs/ zeigt das Verzeichnis der geloeschten Workspace-ID weiterhin, solange ihre Sessions noch existieren; erst nachdem auch diese Sessions beendet sind und ein weiterer Neustart erfolgt, ist ls ~/.config/cipher-mux/runs/ ohne das Verzeichnis
