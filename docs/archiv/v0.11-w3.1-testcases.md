## Testprozess (Uebergabe an Companion)

Dieses Dokument wird clusterweise mit dem User durchgearbeitet. Ein Cluster nach dem anderen — erst wenn ein Cluster gruen ist, kommt der naechste dran.

**Themencluster:**

| # | Cluster | Testcases |
|---|---------|-----------|
| 1 | Grid & Interaction | SP-1 (Session Lifecycle) + SP-3 (LauncherCell + Grid) |
| 2 | Voice | SP-4 (Voice COM) |
| 3 | UI Polish & Sidebar | SP-5 (UI Polish + Sidebar) |
| 4 | Infra & Cross-Cutting | SP-2 (MCP) + Cross-Cutting |

**Ablauf pro Cluster:**

1. User beschreibt was er sieht, Companion hakt Testcases ab oder markiert als FAIL
2. Bugs die nicht in den Testcases stehen aber im selben Bereich auffallen: hier als Zusatz-Items aufnehmen
3. Cluster-Ergebnis zusammenfassen: PASS/FAIL/neue Bugs
4. Ergebnis per `mux_send(topic: "chat")` an den Orchestrator melden — der dispatcht Worker fuer die Fixes
5. Nach Fixes: gleichen Cluster re-testen (nur FAILs + Regressions)
6. Cluster gruen? → naechster Cluster

**Regeln:**
- Ergebnisse direkt in diesem Dokument festhalten (Checkboxen, Kommentare als Unterpunkte)
- Kein Fixing durch den Companion — nur testen und dokumentieren
- Ein Cluster bis es durch ist, nicht zwischen Clustern springen
