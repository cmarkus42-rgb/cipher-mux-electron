# SP-2: MCP + Companion Infrastructure

## Ziel
Companion MCP-Tools funktionsfaehig machen und Persona-Verteilung korrigieren.

## Bugs

### B02 — Companion MCP-Tools nicht geladen (KRITISCH)
**Symptom:** mux_send, mux_read, notes-Tools fehlen im Companion. MCP App-Control komplett nicht funktional.
**Erwartung:** Companion-Session hat Zugriff auf alle cipher-mux MCP-Tools (mux_send, mux_read, mux_sessions, notes_create, notes_read, notes_search etc.)
**Relevante Dateien:**
- `src/main/mcp/mcp-tools.ts` — Tool-Definitionen
- `src/main/mcp/mcp-server.ts` — MCP-Server-Setup
- `src/main/mcp/mcp-auth.ts` — Auth-Handling
- `src/main/agent/adapters/claude-code.ts` — MCP-Injection in Claude-CLI
- `src/main/session/session-manager.ts` — Session-Erstellung mit Capabilities

**Debugging-Ansatz:**
1. Pruefen wie MCP-Tools in Claude-Sessions injiziert werden (--mcp-config? settings.json?)
2. Pruefen ob `companion-mcp: true` Capability korrekt ausgewertet wird
3. Pruefen ob MCP-Server URL und Auth korrekt an Claude CLI uebergeben werden
4. In einer laufenden Companion-Session testen: kann sie MCP-Tools aufrufen?

### B07 — Persona-Verteilung kaputt (HOCH)
**Symptom:** MPO und Orchestrator bekommen Companion-Persona statt ihrer eigenen. Greifen auf globale Mimir-Persona (aus ~/.claude/CLAUDE.md) zurueck.
**Erwartung:** Jede Entity-Rolle bekommt ihre eigene CLAUDE.md mit rollenspezifischer Persona.
**Relevante Dateien:**
- `src/main/session/entity-registry.ts` — Entity-Definitionen
- `src/main/session/entity-assets.ts` — Asset-Verteilung (CLAUDE.md etc.)
- `src/main/session/mpo-template.ts` — MPO-Template
- `src/main/session/orchestrator-template.ts` — Orchestrator-Template
- `src/main/workspace/persona-skill-sync.ts` — Persona-Sync
- `src/shared/persona-types.ts` — Persona-Typen
- `src/main/character/character-defaults.ts` — Default-Character

**Debugging-Ansatz:**
1. Pruefen welche CLAUDE.md in den Entity-Verzeichnissen (`~/.config/cipher-mux/entities/companion/`, `~/.config/cipher-mux/orchestrator/`, `~/.config/cipher-mux/mpo/`) liegt
2. Pruefen ob entity-assets.ts die CLAUDE.md korrekt generiert/kopiert
3. Pruefen ob die Templates eine eigene Persona definieren oder auf einen Default fallen
4. Die Persona-Simplification (siehe Memory: decisions_persona_simplification.md) koennte hier Regressions verursacht haben — es wurde auf eine App-weite Companion-Persona umgestellt, aber MPO/Orchestrator brauchen trotzdem eigene Rollen-Instruktionen

**Wichtig:** Die globale Mimir-Persona in `~/.claude/CLAUDE.md` ist korrekt und soll bleiben. Das Problem ist, dass die Entity-spezifischen CLAUDE.md-Dateien die Rolle nicht ueberschreiben. Jede Entity braucht in ihrer projekt-spezifischen CLAUDE.md eine klare Rollen-Definition die Mimir uebersteuert.

## Testcases

1. Companion-Session starten → MCP-Tools verfuegbar (mux_send, mux_read, notes_*)
2. In Companion: `mux_send` aufrufen → Nachricht erscheint im Message-Bus
3. In Companion: `mux_read` aufrufen → Nachrichten lesbar
4. In Companion: Notes-Tool aufrufen → Note erstellen/lesen funktioniert
5. MPO-Session CLAUDE.md pruefen → enthaelt MPO-Rolle, nicht Companion
6. Orchestrator-Session CLAUDE.md pruefen → enthaelt Orchestrator-Rolle
7. Companion-Session CLAUDE.md pruefen → enthaelt Companion-Rolle

## Qualitaets-Gate
- Alle 7 Testcases PASS
- MCP-Tools in Companion aufrufbar
- Jede Entity hat rollenspezifische CLAUDE.md
- Kein Fallback auf Mimir fuer Entity-Rollen
