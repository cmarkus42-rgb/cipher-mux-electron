## P.1 — Tag-basiertes Notes-Scoping (ersetzt Ordner-Scoping)

**Prioritaet:** MUST (Fundament fuer C.1 und alles was mit Notes zu tun hat)
**Quelle:** moreismore/konzept-projekt-workspace-struktur.md

### Kern-Aenderung

**Status Quo:** Notes haben zwei Scopes — `global/` und `workspace-<id>/`. Das erzwingt Ordner-Hierarchie. Notes gehoeren entweder "allen" oder "einem Workspace".

**Neu:** Scope-Zuordnung komplett ueber Tags. ALLE Notes sind global gespeichert (ein Verzeichnis). Ein Workspace definiert `defaultTags: string[]` (freie Tags, keine Prefix-Konvention erzwungen). Wenn der Workspace aktiv ist, werden diese Tags automatisch als Filter vorausgewaehlt in der Sidebar. Kein separater `workspace-<id>/`-Scope mehr.

**Vorteile:**
- Notes koennen mehreren Workspaces zugeordnet sein (Multi-Tag)
- Keine starre Ordnerstruktur, alles durchsuchbar
- Workspace-Wechsel aendert nur den aktiven Filter, nicht den Zugriff
- Bug-Reports und Feature-Requests landen automatisch im richtigen Projekt-Kontext

### Technische Umsetzung

**note-manager.ts:**
- `list(scope)` → Scope-Parameter ENTFAELLT. Stattdessen: `list(filterTags?: string[])` — alle Notes laden, optional nach Tags filtern
- Dateipfad vereinfacht: `{notesDir}/{id}.md` (kein Scope-Unterordner mehr)
- Abwaertskompatibilitaet: Beim Start einmalig pruefen ob `global/` und `workspace-*/` Ordner existieren → Migration (siehe P.3)

**SidebarPanel.tsx (Notes-Sektion):**
- Wenn Workspace aktiv: `defaultTags` aus Workspace-Config als vorausgewaehlte Filter-Chips
- User kann Filter-Chips entfernen/hinzufuegen (Session-temporaer)
- Ohne Workspace: kein Default-Filter, alle Notes sichtbar

### Akzeptanzkriterien
- [ ] Notes werden in einem flachen Verzeichnis gespeichert (kein Scope-Ordner)
- [ ] Workspace-Default-Tags als vorausgewaehlte Filter in der Sidebar
- [ ] Notes ohne Workspace-Tags sind trotzdem sichtbar (kein "versteckt")
- [ ] Workspace-Wechsel aendert nur den Filter, nicht den Zugriff

## P.3 — Migration bestehender Notes (Ordner → flach + Tags)

**Prioritaet:** MUST (einmalig beim ersten Start nach Update)

### Migrations-Logik (in note-manager.ts)

Beim App-Start pruefen:
1. Existiert `{notesDir}/global/`? → Alle .md Files nach `{notesDir}/` verschieben

## C.1 — Notes-Verwaltungssystem mit Tag-Hierarchie

**Prioritaet:** MUST
**Baut auf P.1 auf:** Tag-basiertes Scoping ist die Grundlage.

### Kern-Konzept
Slash-Tags als virtuelles Ordnersystem: `bugs/ui/grid`, `status/open`, `feature/voice`.
UI rendert aufklappbaren Baum (links), gefilterte Liste (rechts).

### UI-Aufbau (NotesTreeView.tsx)

**Layout in SidebarPanel Notes-Sektion:**
```
┌─────────────────────────┐
│ 🔍 [Suchfeld________]  │
│                         │
│ ▼ bugs/ (12)            │
│   ▼ ui/ (8)             │
│     grid (3)            │
│     voice (2)           │
│     sidebar (3)         │
│   mcp (4)               │
│ ▼ feature/ (15)         │
│   voice (5)             │
│   notes (10)            │
│ ▶ status/ (20)          │
│                         │
│ ─────────────────────── │
│ Note-Liste (gefiltert): │
│ ┌─────────────────────┐ │
│ │ Grid verschwindet   │ │
│ │ bugs/ui/grid        │ │
│ ├─────────────────────┤ │
│ │ Copy Paste broken   │ │
│ │ bugs/ui/notes       │ │
│ └─────────────────────┘ │
└─────────────────────────┘
```

### Funktionen
- **Baumnavigation** filtert die Liste: Klick auf `bugs/ui/` zeigt nur Notes mit Tags unter `bugs/ui/*`
- **Tag-Ausschluss:** Tags koennen auch als Negativ-Filter gesetzt werden (Beispiel: `-processed` blendet alle Notes mit Tag `processed` aus). UI: Klick = Include (gruen), nochmal Klick = Exclude (rot/durchgestrichen), nochmal = neutral. Typischer Use-Case: "zeige mir alle Bugs OHNE processed"
- **Suchfeld:** FlexSearch ueber Titel, Tags, Body
- **Drei Textlevel:** Titel (immer sichtbar), Tags (kompakt unter Titel), Preview (hover — erste 2 Zeilen Body)
- **Einfachklick** = Select/Preview
- **Doppelklick** = Editor oeffnen (NotesCell oder Sidebar-Editor)
- **Mehrfachselektion** fuer Bulk-Ops (Delete, Tag-Aenderung)
- **LLM-gestuetzte Reorganisation:** Wenn >50 Tags → Vorschlag-Button "Tags aufraeumen" der Zusammenfuehrungen und Umstrukturierungen vorschlaegt

### Technische Basis
- **Dateien bleiben MD + YAML-Frontmatter** (kein DB-Lock-in)
- **FlexSearch** (~12k Stars, MIT) fuer Volltextsuche im Browser — `npm install flexsearch`
- **Tag-Index** aus Frontmatter beim Start gebaut (in note-tagging.ts)
- **Alte flache Tags** landen auf oberster Ebene (abwaertskompatibel)
- **Tag-Hierarchie:** Slash als Separator. `bugs/ui/grid` = 3 Ebenen. UI baut Baum daraus.

### Akzeptanzkriterien
- [ ] Aufklappbarer Tag-Baum in der Sidebar-Notes-Sektion
- [ ] Klick auf Tag filtert Note-Liste
- [ ] FlexSearch-Suche ueber Titel, Tags, Body funktioniert
- [ ] Drei Textlevel korrekt gerendert
- [ ] Einfach-/Doppelklick-Verhalten
- [ ] 100+ Notes fluessig darstellbar

## C.3 — Copy & Paste im Notes-Editor

**Prioritaet:** HOCH

### Problem
Cmd+C / Cmd+V funktioniert nicht im Notes-Editor (CodeMirror 6).

### Aktuelle Implementierung (NoteEditor.tsx Z.147-198)
Es gibt bereits einen Workaround:
- Capture-Phase Listener fuer Cmd+C/V/X
- Liest CM6-Selection via `view.state.sliceDoc(from, to)`
- Schreibt/liest `navigator.clipboard`

### Vermutete Ursache
Electron's globaler Keyboard-Handler (`webContents` Menu-Roles) feuert VOR dem Capture-Phase-Listener. Das Event wird geschluckt bevor CM6 es sieht.

### Loesung
1. **Electron Menu Roles pruefen:** In `src/main/` nach Menu-Definition suchen. Wenn Cmd+C/V als `role: 'copy'`/`role: 'paste'` registriert sind, feuern sie auf `webContents`-Ebene und CM6 bekommt nichts.
2. **Fix:** Entweder Menu-Roles entfernen und komplett custom handlen, ODER im NoteEditor per `beforeinput`-Event die Clipboard-Aktionen abfangen.
3. **Alternativer Ansatz:** `webContents.on('before-input-event')` im Main-Prozess nutzen um Cmd+C/V an den Renderer durchzuleiten wenn ein CM6-Editor fokussiert ist.

### Akzeptanzkriterien
- [ ] Cmd+C kopiert markierten Text im Notes-Editor
- [ ] Cmd+V fuegt aus Clipboard ein
- [ ] Cmd+X schneidet aus
- [ ] Cmd+A selektiert alles
- [ ] Funktioniert auch in InfoSettingsView und anderen Textfeldern
