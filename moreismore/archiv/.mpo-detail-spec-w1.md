## Anforderung A.1 — Grid-Session verschwindet beim Verschieben

**Schwere:** Hoch
**Symptom:** Session verschwindet visuell beim Verschieben (z.B. von oben-rechts nach unten-links). Session lebt in tmux weiter, ist aber nicht im Grid und nicht im Hintergrund sichtbar.

**Reproduktion:**
1. 2x2 Grid, Companion oben links, Orchestrator oben rechts
2. Orchestrator nach unten links verschieben (Drag&Drop)
3. Session verschwindet, Zelle zeigt gestrichelte Umrandung
4. Companion nach oben rechts verschieben → Orchestrator taucht wieder auf

**Root-Cause-Analyse:**
Die `swapSlots()` Funktion in `grid-types.ts` (Z.79) tauscht zwei Slot-Eintraege. Problem: Wenn der Ziel-Slot leer ist (sessionId: null), wird ein Swap mit null gemacht. Die Quell-Session geht in den null-Slot, der null geht in den Quell-Slot. Aber die Rendering-Logik in SessionGrid.tsx prueft `slot.sessionId` — wenn der Slot nach dem Swap nicht korrekt aktualisiert wird (z.B. Race Condition bei State-Update), verschwindet die Session.

**Untersuche:**
1. `swapSlots()` in grid-types.ts Z.79 — wird die Slot-Zuweisung atomar gemacht oder gibt es eine Race Condition?
2. SessionGrid.tsx Drag&Drop-Handler (Z.66-79) — wird `onSwap` synchron oder async aufgerufen?
3. State-Update-Kette: Swap → IPC → Config-Store → Re-Render. Gibt es ein Timing-Problem?

**Akzeptanzkriterien:**
- [ ] Session bleibt nach Verschieben in die Zielzelle sichtbar
- [ ] Quell-Zelle zeigt LauncherCell ("+") nach Verschieben
- [ ] Verschieben auf leere UND belegte Zellen funktioniert
- [ ] Grid-State wird korrekt persistiert nach Verschieben

## Anforderung A.3 — Verwaiste Sessions blockieren Preset-Auswahl

**Schwere:** Hoch
**Symptom:** Alle 5 Presets zeigen "laeuft" obwohl nur 2 sichtbar sind. Geister-Sessions blockieren neue Starts.

**Root-Cause-Analyse:**
Entity-Status in `app.tsx` (Z.145-152) wird aus `entitySessionIds` bestimmt — einem Memo das true/false pro Entity liefert. Die Frage ist: Woher kommen die Session-IDs?

In `session-manager.ts` gibt es `entitySessionIds: Map<EntityId, string>`. Beim App-Start wird `recover()` (Z.256-294) aufgerufen, der tmux-Sessions mit der App-State-Datei (`sessions.json`) abgleicht. Wenn tmux-Sessions existieren die nicht in sessions.json stehen (oder umgekehrt), entsteht die Diskrepanz.

**Loesung (nicht Symptom-Fix, sondern Root-Cause):**
1. `recover()` erweitern: Nur Sessions als "entity-linked" markieren die SOWOHL in tmux ALS AUCH in sessions.json existieren
2. Verwaiste tmux-Sessions (prefix `cmux-`) die nicht in sessions.json stehen → cleanupDeadSessions() erweitern
3. entitySessionIds nur setzen wenn Session tatsaechlich im Grid ODER im Hintergrund ist

**Akzeptanzkriterien:**
- [ ] Preset zeigt "laeuft" NUR wenn Session tatsaechlich sichtbar (Grid oder Hintergrund)
- [ ] Verwaiste tmux-Sessions werden beim App-Start aufgeraeumt
- [ ] Nach Cleanup: alle Presets startbar

## Anforderung H.4 — mux_send: Duale Delivery (tmux + Message-Bus)

**Schwere:** Mittel
**Architektur-Entscheidung (steht):** Jedes `mux_send` mit Push-Delivery soll BEIDES tun:
1. tmux send-keys an die Ziel-Session (wie bisher)
2. Eintrag im Message-Bus (sichtbar in Sidebar)

**Aktueller Code (mcp-tools.ts Z.71-123):**
- Message wird in den Bus geschrieben (Z.~85)

**Loesung:**
Message-Bus-Eintrag IMMER machen (vor dem sendKeys-Aufruf). Push-Delivery ist zusaetzlich, nicht alternativ.

**Akzeptanzkriterien:**

- [ ] Bei Push-Delivery: Nachricht erscheint SOWOHL in Sidebar ALS AUCH in der tmux-Session

## Anforderung H.6 — mux_send Push-Delivery Base64-Blob

**Schwere:** Mittel
**Symptom:** Push-Delivery schickt base64-encoded echo-Kommando statt Klartext.

**Root-Cause:** `escapeForTmux()` in mcp-tools.ts (gefunden bei Exploration):
```typescript
if (text.length > 500) {
  const b64 = Buffer.from(text).toString('base64')
  return `echo '${b64}' | base64 -d`
}
```

Das ist ein Shell-Kommando, kein Klartext. Der tmux send-keys schickt das buchstaeblich als Tasteneingabe in die Session. Das ergibt Sinn wenn die Ziel-Session ein Shell-Prompt ist, aber NICHT wenn die Ziel-Session ein Claude-Prompt ist.

**Loesung:**
- Fuer Claude-Sessions: IMMER Klartext senden, auch bei >500 Zeichen
- tmux send-keys mit `-l` (literal) Flag oder Hex-Encoding kann beliebig langen Text senden
- `escapeForTmux()` entfernen oder auf reines Escaping (ohne base64) reduzieren

**Akzeptanzkriterien:**
- [ ] Nachrichten jeder Laenge erscheinen als Klartext in der Ziel-Session
- [ ] Keine base64-Kodierung sichtbar
- [ ] Sonderzeichen (Anfuehrungszeichen, Semikolons) korrekt escaped

## Anforderung H.9 — Terminal-Zeilen (xterm.js fit()-Bug)

**Schwere:** Niedrig (Workaround: Doppelhoehe)
**Symptom:** Zeilen fallen auseinander beim Oeffnen einer Session und beim Zurueckholen aus Hintergrund.

**Recherche liegt vor:** `docs/research-context-and-xterm-2026-04-27.md`

**Loesung (aus Recherche):**
1. **Visibility-Gate:** `terminal.fit()` nur aufrufen wenn Container sichtbar (display !== none, offsetWidth > 0)
2. **ResizeObserver** pro Grid-Zelle mit 150ms Debounce
3. **Double-Fit** bei Session-Attach: fit() → 50ms Pause → fit()
4. **tmux resize-pane Synchronisation:** Nach fit() explizit `tmux resize-pane -t {target} -x {cols} -y {rows}`

**Akzeptanzkriterien:**
- [ ] Session zeigt korrekte Zeilenlaenge beim Oeffnen
- [ ] Session zeigt korrekte Zeilenlaenge nach Zurueckholen aus Hintergrund
- [ ] Grid-Resize passt Terminal korrekt an
