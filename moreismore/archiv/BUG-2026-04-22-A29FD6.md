# Bug: MCP-Session wird sporadisch nicht erreichbar (Session not found / Reconnect-Failure)

**Bug-ID:** BUG-2026-04-22-A29FD6
**Severity:** High — Orchestrator verliert Steuerungsfaehigkeit
**Reported:** 2026-04-22
**Reporter:** Orchestrator-Session
**Projekt:** cipher-mux-electron
**projectPath:** /Users/Shared/Nextcloud/Claude/ClaudeCode01/cipher-mux-electron

## Symptom

Die Orchestrator-Session (und potenziell jede Worker-Session) verliert sporadisch den Zugriff auf die MCP-Tools. Claude Code meldet, dass die cipher-mux MCP-Tools nicht verfuegbar sind, obwohl der Server laeuft und erreichbar ist. Nach einem `/clear` oder Session-Neustart funktioniert die Verbindung wieder.

## Analyse

### Root Cause 1: MCP-Session-Lebenszyklus nicht an Claude-Code-Session gekoppelt

Der MCP-Server (`mcp-server.ts`) verwaltet Sessions in einer In-Memory-Map (`this.sessions: Map<string, McpSession>`). Jeder Claude-Code-Client bekommt bei `initialize` eine eigene Session-ID. Problem:

- **Kein Session-Timeout:** Sessions werden nur bei explizitem DELETE entfernt (Zeile 264-274). Es gibt keinen Timeout oder Heartbeat.
- **Kein Reconnect-Handling:** Wenn Claude Code intern reconnected (z.B. nach Context-Kompression, `/clear`, oder internem Reset), schickt es moeglicherweise eine neue `initialize`-Request. Die alte Session bleibt als Zombie in der Map.
- **Session not found:** Wenn Claude Code seine gecachte `Mcp-Session-Id` verliert (z.B. nach `/clear`), schickt es Requests mit der alten ID → 404 "Session not found". Danach schickt es eine neue `initialize`-Request, aber die Tool-Liste wird moeglicherweise nicht korrekt neu geladen.

### Root Cause 2: Session-Akkumulation ohne Cleanup

Jede `initialize`-Request erzeugt ein neues `McpServer + Transport`-Paar (Zeile 103-128). Bei haeufigerem Reconnect (z.B. durch `/clear` oder Context-Resets) akkumulieren sich verwaiste Sessions:
- Jede Session registriert alle 13 Tools neu
- Kein Garbage Collection fuer verwaiste Sessions
- Potenzielle Memory-Leaks im Electron-Main-Process bei Langzeitbetrieb

### Root Cause 3: .mcp.json vs settings.json Divergenz

Zwei Mechanismen konkurrieren um die MCP-Registrierung:
1. `.mcp.json` im Projektverzeichnis (Zeile in session-manager.ts, Fallback)
2. `claude mcp add-json` in project-scope settings (Zeile 367-388 in session-manager.ts)

Die Orchestrator-Session nutzt `.mcp.json` (Datei existiert unter `/Users/cipher/.config/cipher-mux/orchestrator/.mcp.json`). Wenn `claude mcp add-json` ebenfalls gelaufen ist, koennten doppelte Eintraege oder Konflikte entstehen.

### Root Cause 4: Fehlende Fehlerbehandlung bei Session-Verlust

Wenn der MCP-Server 404 "Session not found" zurueckgibt, hat Claude Code keinen Mechanismus zum automatischen Re-Initialize. Der Client muesste:
1. Erkennen, dass die Session ungueltig ist
2. Die Session-ID verwerfen
3. Eine neue `initialize`-Request senden

Das passiert nicht automatisch — Claude Code behandelt den 404 als Tool-Fehler und gibt auf.

## Reproduktion

1. Orchestrator-Session starten
2. MCP-Tools nutzen (funktioniert)
3. `/clear` ausfuehren
4. MCP-Tools erneut nutzen → sporadisch "not available" oder Fehler

## Fix-Vorschlaege

### 1. Session-Timeout (Quick Fix)
```typescript
// In mcp-server.ts: Sessions nach 30 Minuten Inaktivitaet aufraeumen
private readonly SESSION_TIMEOUT = 30 * 60 * 1000

private startSessionGC(): void {
  setInterval(() => {
    const now = Date.now()
    for (const [id, session] of this.sessions) {
      if (now - session.lastActivity > this.SESSION_TIMEOUT) {
        session.transport.close()
        session.mcpServer.close()
        this.sessions.delete(id)
      }
    }
  }, 60_000)
}
```

### 2. Graceful Re-Initialize
Wenn ein Request mit unbekannter `Mcp-Session-Id` kommt UND der Body eine `initialize`-Methode enthaelt, die alte Session-ID ignorieren und eine neue Session erzeugen statt 404 zu senden.

### 3. Session-Limit
Maximal N Sessions pro Client/Quelle. Bei Ueberschreitung die aelteste Session schliessen.

### 4. Health-Endpoint
Ein simpler GET `/health` Endpoint (ohne Auth) der 200 zurueckgibt wenn der Server laeuft. Claude Code koennte das als Pre-Check nutzen.
