## E.2 — Preset-Editor im Companion-Fenster

**Prioritaet:** MUST

### Konzept
Der Companion-Editor (WorkspacesWindow, Companion-Tab) wird um einen Preset-Editor erweitert. Der Preset-Editor zeigt alle Entities/Presets an und macht sie auf Ebene ihrer Bestandteile bearbeitbar.

### UI-Design

**Aufbau:**
- Links: Preset-Liste (wie Character-Liste, aber fuer Entities)
- Rechts: Editor mit 4 Reitern

**Reiter:**
1. **Rolle** — 1-3 Saetze was die Entity tut
2. **Faehigkeiten** — Was die Entity kann (Skillset-Block)
3. **Arbeitsregeln** — Spezifische Regeln fuer diese Rolle
4. **Scope** — Was die Entity ist und NICHT ist

**Anforderungen:**
- Scrollbares Fenster, Mindesthoehe 400px
- Warnung vor Editierung: "Preset-Definitionen beeinflussen das Verhalten aller Sessions mit diesem Preset. Fortfahren?" mit "Abbrechen" / "Bearbeiten"
- Neue Presets erstellen: Button "+", legt neues Entity-Verzeichnis an
- Companion Memory wird NICHT im Editor angeboten (teilt sich ohnehin)
- Man soll die Struktur sehen koennen (Transparenz)

**Abgrenzung:**
- Persona-Editor (existiert): Editiert den CHARAKTER (Ton, Humor) → wirkt global
- Preset-Editor (neu): Editiert die FAEHIGKEITEN pro Entity → wirkt entity-spezifisch

### Technische Umsetzung

**Neue Komponente:** `PresetEditor.tsx`
- Rendert als Tab neben dem existierenden Character-Editor in CompanionTab.tsx
- Laedt Presets via neuen IPC-Channel `IPC.PRESETS_LIST`
- Speichert Aenderungen via `IPC.PRESETS_SAVE`
- Preset-Daten kommen aus den Entity-CLAUDE.md-Dateien (geparst nach Sektionen)

**Backend:** `entity-registry.ts` erweitern
- `listPresets()`: Scannt Entity-Verzeichnisse, parst CLAUDE.md nach Sektionen
- `savePreset(id, sections)`: Schreibt Sektionen zurueck in CLAUDE.md
- `createPreset(name)`: Legt neues Entity-Verzeichnis an mit Template-CLAUDE.md
- `deletePreset(id)`: Loescht Entity-Verzeichnis (mit Warnung)

**Neue IPC-Channels:**
- `IPC.PRESETS_LIST` → EntityRegistry.listPresets()
- `IPC.PRESETS_SAVE` → EntityRegistry.savePreset()
- `IPC.PRESETS_CREATE` → EntityRegistry.createPreset()
- `IPC.PRESETS_DELETE` → EntityRegistry.deletePreset()

### Akzeptanzkriterien
- [ ] Preset-Editor als Tab im Companion-Fenster erreichbar
- [ ] Alle registrierten Presets sichtbar
- [ ] 4 Reiter pro Preset editierbar
- [ ] Warnung vor Editierung
- [ ] Neue Presets erstellbar
- [ ] Gespeicherte Aenderungen wirken bei naechstem Entity-Start

```typescript
export class EntityScanner {
  private readonly entitiesDir = path.join(os.homedir(), '.config/cipher-mux/entities')

  // Beim App-Start: Scan + Registration
  async scanAndRegister(): Promise<EntityPreset[]> {
    const dirs = await fs.readdir(this.entitiesDir)
    const presets: EntityPreset[] = []

    for (const dir of dirs) {
      const claudeMd = path.join(this.entitiesDir, dir, 'CLAUDE.md')
      if (await fileExists(claudeMd)) {
        const parsed = await this.parseEntityClaudeMd(claudeMd)
        presets.push({
          id: dir,
          displayName: parsed.roleName,
          sections: parsed.sections,
          color: parsed.color || this.defaultColor(dir),
          // ...
        })
      }
    }

    // Orchestrator und MPO aus bekannten Pfaden ergaenzen
    presets.push(...this.getBuiltinEntities())

    return presets
  }
}
```

## P.4 — Workspace = Projekt-Kontext (Config-Erweiterung)

**Prioritaet:** MUST
**Quelle:** moreismore/konzept-projekt-workspace-struktur.md

### Kern-Aenderung

Ein Workspace definiert nicht nur Grid-Belegung und Theme, sondern auch:
- **projectPath** — der Arbeitsordner fuer alle Sessions in diesem Workspace (bereits vorhanden)
- **defaultTags: string[]** (NEU) — freie Tags, werden als Filter in der Sidebar vorausgewaehlt und automatisch an neue Notes angehaengt
- **entityPresets** (NEU, SHOULD) — welche Sessions mit welchen Einstellungen gestartet werden

### Technische Umsetzung

**Workspace-Datenmodell erweitern** (workspace-manager.ts oder types):
```typescript
interface Workspace {
  id: string
  name: string
  cols: number
  rows: number
  cells: WorkspaceCell[]
  theme?: string
  projectPath?: string       // existiert bereits
  defaultTags?: string[]     // NEU — freie Tags, keine Prefix-Konvention
  entityPresets?: string[]   // NEU/SHOULD — welche Entities auto-starten
}
```

**Session-Start:** Wenn Workspace aktiv und `projectPath` gesetzt: Entity-Sessions starten in diesem Verzeichnis (nicht im Default-Verzeichnis). Alle Sessions wissen automatisch an welchem Projekt sie arbeiten.

**Zusammenspiel mit Worker 3 (P.1/P.2):** Worker 3 implementiert die Notes-Seite (Filterung, Auto-Tagging). Du lieferst die Config-Grundlage (defaultTags im Workspace-Modell).

### Akzeptanzkriterien
- [ ] Workspace-Config enthaelt `defaultTags: string[]`
- [ ] Tags sind im Workspace-Editor setzbar
- [ ] Aktiver Workspace liefert `defaultTags` per IPC an den Renderer
