# Detail-Spec: Worker 4 — Theme-Editor + MPO Persona

## Bugs

### RT-W2: Theme-Editor ueberschreibt eingebaute Themes (MUST)

**Dateien:**
- `src/renderer/hooks/useTheme.ts` (Theme-State und Save-Logik)
- `src/renderer/themes.json` (eingebaute Theme-Definitionen)
- `src/renderer/components/InfoSettingsView.tsx` (Theme-Editor UI)
- Evtl. `src/renderer/components/NoteEditor.tsx` (hat auch Theme-Editor-Referenz)

**Problem:** Wenn man ein eigenes Theme editiert und speichert, werden die Farben auf eingebaute Themes uebertragen. "Cipher Ivory" wurde durch editierte Farben ueberschrieben.

**Fix-Strategie:**
1. Eingebaute Themes (aus themes.json) muessen unveraenderlich sein — readonly/frozen
2. Beim Speichern pruefen ob das aktive Theme ein eingebautes ist → nur Custom-Themes duerfen ueberschrieben werden
3. Theme-State muss zwischen eingebauten und Custom-Themes unterscheiden

**Zusaetzlich:** Cipher Ivory aus git wiederherstellen:
```bash
git checkout HEAD -- src/renderer/themes.json
git checkout HEAD -- src/renderer/styles/theme-cipher-ivory.css
```
Pruefen ob themes.json oder die CSS-Datei ueberschrieben wurde.

**Screenshot:** `~/Desktop/Bildschirmfoto 2026-04-30 um 11.53.31.png`

**Testcase:** Eigenes Theme erstellen → Farben editieren → auf Cipher Ivory wechseln → zeigt originales Cipher Ivory, nicht die editierten Farben.

### RT-4: MPO hat keine Persona-Sektion (MUST)

**Dateien:**
- `~/.config/cipher-mux/entities/mpo/CLAUDE.md` (aktuelle MPO-Instruktionen)
- `~/.config/cipher-mux/entities/audit/CLAUDE.md` (Referenz fuer dynamische Persona-Injection)
- `src/main/session/entity-assets.ts` oder `entity-registry.ts` (Persona-Injection bei Session-Start)

**Problem:** MPO-CLAUDE.md hat keine Persona-Sektion. Faellt auf Mimir aus der globalen CLAUDE.md zurueck.

**Fix:** Persona-Sektion in MPO-CLAUDE.md einfuegen. Pruefen wie audit die dynamische Injection macht und das gleiche Pattern anwenden. Falls die Persona-Injection im Code passiert (entity-assets.ts), dort sicherstellen dass MPO inkludiert ist.

WICHTIG: Die CLAUDE.md hat bereits eine Persona-Sektion mit Wayne. Diese muss als Default-Persona drinbleiben, aber die dynamische Injection soll sie zur Laufzeit ueberschreiben koennen — genau wie bei audit.

**Testcase:** MPO-Session starten → Persona ist Wayne (oder aktive Companion-Persona), NICHT Mimir.
