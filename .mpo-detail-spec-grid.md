# Detail-Spec: Worker 2 — Grid Fixes

## Bugs

### RT-10: Grid-Place Session doppelt angezeigt (MUST — REGRESSION!)

**Dateien:**
- `src/main/mcp/mcp-tools.ts` (grid_place Handler)
- `src/main/session/session-manager.ts` (Session-Platzierung)
- `src/renderer/hooks/useGrid.ts` (Grid-State)
- `src/renderer/components/SessionGrid.tsx` (Rendering)

**Problem:** `mux_grid_place` platziert Session in Zielzelle, aber Session bleibt AUCH in der alten Zelle sichtbar. Das ist eine Regression — T-GR.7 war vorher PASS.

**Vermutete Ursache:** Beim EntityPickerPopup-Refactoring oder Grid-Place-Fix wurde vermutlich vergessen, die alte Zelle zu raeumen bevor die Session in die neue Zelle gesetzt wird.

**Fix-Strategie:**
1. Grid-Place-Handler finden (mcp-tools.ts oder session-manager.ts)
2. Pruefen ob die alte Grid-Position geraeumt wird bevor die neue gesetzt wird
3. Falls der State im Renderer liegt: useGrid.ts pruefen ob beim Place die alte Zelle entfernt wird

**Testcase:** Session in [0,0] → mux_grid_place auf [2,0] → Session NUR in [2,0], [0,0] ist leer.

### GridSelector-Popup erscheint nur beim MPO-Start (SHOULD)

**Dateien:** `src/renderer/components/GridPlacementPopup.tsx`, Session-Start-Logik
**Problem:** Beim MPO-Start erscheint das GridSelector-Popup obwohl freie Zellen vorhanden sind. Bei Companion, Orchestrator, Refinement passiert das nicht.
**Vermutete Ursache:** MPO hat evtl. einen Sonderpfad in der Entity-Logik oder das Projekt-Pfad-Matching greift anders (`~/.config/cipher-mux/mpo` vs. `entities/xxx`).

**Testcase:** MPO starten bei verfuegbaren freien Zellen → kein Popup, direkte Platzierung wie bei anderen Entities.
